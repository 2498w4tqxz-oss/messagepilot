# Expanded acceptance — 2026-10-07

Testing used one explicitly authorized self-chat on macOS with SIP enabled, plus a newly created iPhone 17 / iOS 26.5 simulator without an Apple Account. The simulator used synthetic cards, images, identities, credentials and an isolated HTTPS gateway. No other personal conversation, Contacts or Find My data was queried. Simulator Messages uses seeded conversations and simulated delivery; it cannot establish Apple-network delivery or a physical recipient's experience.

## Previous live evidence retained

The prior [rich messaging acceptance](RICH_MESSAGING_VERIFICATION.md) covers four text styles, eight text effects, four bubble effects, eight screen effects, editing, unsending, correctly targeted replies, adding/removing all six standard Tapbacks, and PNG/GIF/MP4 self-chat delivery. These were not all rerun in this expanded session. Opening the chat was verified previously; remote read-receipt delivery is still unverified. Native arbitrary font families are not implemented.

## Not accepted in this environment

- GIPHY and other third-party extension workflows: the simulator has no App Store account or installed third-party extensions. The built-in #images search/results UI opened, but no GIF was sent through it.
- Built-in sticker-browser workflows, Memoji/Genmoji, Digital Touch, Check In, Image Playground, audio recording, camera media, Apple Cash and shared conversation backgrounds: no completed end-to-end acceptance. Generic recipes are not blanket compatibility proof.
- Real passkey registration/sign-in requires configured relying-party/Associated Domains and system user verification. Cryptographic server fixtures do not prove this Apple flow.
- ARKit tracking, RoomPlan and real camera capture require appropriate physical hardware. Find My requires an explicitly scoped agent environment; personal Find My was not inspected.
- Physical-device provisioning, independent generated-app signing/install, two-account isolation under real Apple identities, VM installation/Apple activation/takeover, reboot recovery, other locales and group-chat behavior remain unverified. No physical iPhone or dedicated Apple credentials were supplied.
- Restricted incoming-message streaming and history pagination are **not implemented**; explicit reads return at most 50 recent messages.

## Speed

The four-photo command took **25,276 ms** and the Confetti regression **18,131 ms** from gateway submission to native result. These are individual samples, not a distribution or recipient-render latency. They do not establish the desired speed advantage. Native UI automation remains the bottleneck; the earlier millisecond synthetic dispatch benchmark excludes it.

## Changes exercised

The restricted worker now accepts `messages.send` with `filePaths` for 2–20 PNG/JPEG files inside its enrolled workspace. It resolves symlinks, validates files, refuses an existing draft, checks the exact attachment-marker count, submits once and reconciles within the bound chat. Photo staging replaces the clipboard, clears it only if unchanged and never reads prior clipboard contents. A mismatched/uncertain result is not automatically resent. The unrestricted native transport explicitly refuses this new collection argument.

Resident native waits now pump the run loop so foreground-application notifications stay current. Pairing input disables automatic casing/correction and rejects short credentials before writing them. The simulator harness supports bounded pauses and paced typing; rapid SecureField input was observed dropping characters. Extension controls have unique action identifiers and keyboard focus management. The page indicator had covered the Select button; removing that overlap restored the authenticated callback.

The final TypeScript build and all 40 tests pass. Both native Swift executables build in release mode, and all four pure Swift payload tests pass. The signed simulator host/extension/harness build-for-testing succeeds. Feature-level acceptance above relies on actual UI, gateway responses and persisted evidence, not merely a green XCTest recipe: a recipe can finish while the requested product outcome still fails.
